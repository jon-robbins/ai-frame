## APPENDIX A — Proposed EXP-017 Full Definition (PLANNED)

**Goal:** 4-panel 256×128 2×2 topology end-to-end validation; verify that Nano-driven content correctly crosses both the vertical seam (x=128 within each 2-panel row) AND horizontal seam (y=64 between top/bottom rows) simultaneously; establish that 2-row sync is dashboard-tolerable (no worse tearing than acceptable); confirm that the chosen controller topology works for 4 panels. This is Milestone 3.

**Status:** PLANNED

**Depends-On:** M2 gate pass AF-091 + MG ADR-016 architecture decision (so we know if it's WF4 or multi-ESP32; actually it can be set up pre-decision for both but EXP procedure describes both)

**Hardware list:**
- (a) Panels #1..#4 × 4
- (b) Power harness branches #1..#4 (4 of 8 used)
- (c) WF4 or 2× ESP32+HCT
- (d) HUB75 cables 3 (panel1→panel2 in top row, panel3→panel4 in bot row, WF4 X1→panel1, X2→panel3 OR ESP32 ctrl#1→panel1, ctrl#2→panel3)
- (e) Nano with M2 software baseline + AF-101 4-panel framebuffer extension

**Hypothesis:** A single WF4 with X1/X2 outputs OR 2 independent ESP32 controllers with per-row Nano crop-split transport can correctly render content across all 4-panel seams without visible artifacts worse than dashboard-tolerable tearing.

**Preconditions:**
1. M2 gate pass for the respective controller
2. Panels #3 and #4 re-verified (AF-097)
3. Power branches #3/#4 correctly terminated
4. Correct row-controller map documented

**Procedure:**

1. **Physical placement top/bottom rows on bench.** Retrieve panels #3 and #4 from storage. Layout 2 rows × 2 columns on ESD mat: top row = panel #1 (left) + panel #2 (right, chain from panel1 OUT); bottom row = panel #3 (left) + panel #4 (right, chain from panel3 OUT). Confirm top-edge orientation markers on all 4 panels match. (Covered by AF-097)
2. **WF4 or ESP32 topology wiring per AF-098 or AF-100.** WF4 winner: X1 → top-row panel1 IN; X2 → bottom-row panel3 IN. OR multi-ESP32 winner: controller#1 HCT → top-row panel1 IN; controller#2 HCT → bottom-row panel3 IN. (Covered by AF-098 or AF-100)
3. **Software framebuffer split implemented (AF-101).** Nano canonical framebuffer.new(256,128). Pillow 4-line content. Split into 2 row-crops: top-crop (0,0)-(255,63) to X1/controller#1; bot-crop (0,64)-(255,127) to X2/controller#2. Transport send_frame each to respective controller. (Covered by AF-101)
4. **First-light check each row independently (AF-102/AF-103).** Send a full 256×64 solid color test to top-row controller only: confirm top 2 panels light up correct colors, left/right order. Repeat for bottom-row. Then send crops: verify top-crop renders on top, bottom-crop on bottom, no cross. (Covered by AF-102 WF4 or AF-103 ESP32)
5. **Vertical seam verification in top row (AF-104 subset).** At y=0..63, run: (a) horizontal gradient smooth across x=128 seam, no banding; (b) vertical seam text straddling seam, letters half on panel1 half on panel2; (c) 1px vertical line at x=128 continuous across panel1→panel2 outputs. Close-up photos. (Covered by AF-104 top-row subset)
6. **Vertical seam verification in bottom row (AF-104 subset).** At y=64..127, same 3 checks (a,b,c) on panels 3→4. Close-up photos. (Covered by AF-104 bottom-row subset)
7. **Horizontal seam verification (AF-104 subset).** 1px horizontal line at y=64 continuous across full 256 width. Horizontal gradient y=0→127. Text straddling the horizontal seam at x≈128. No discontinuity between top-row panel outputs and bottom-row panel outputs. Close-up photo. (Covered by AF-104 horizontal subset)
8. **BOTH-seams-simultaneous diagonal or circle at center (128,64) (AF-104).** Draw 1px anti-aliased diagonal line from (100,36) to (156,92) crossing exactly (128,64). OR draw a 20 px diameter circle centered at (128,64). Confirm no break at either seam: the line/circle is continuous across the 4-corner meeting point. Close-up macro photo. (Covered by AF-104 both-center test)
9. **Row sync test video capture (AF-105).** Update both rows with alternating full-frame checkerboard as fast as possible. Video record ≥10 full flips with phone camera at ≥30 fps. Measure inter-row delta (time difference between top row flip visible and bottom row flip visible). Max delta across 10 flips ≤ 2 s preferred, ≤5 s acceptable. (Covered by AF-105)
10. **Full coordinate grid + corner/boundary labels (AF-106).** Full 256×128 black canvas with: 1px white grid every 32 px; corner labels TL=(0,0) TR=(255,0) BL=(0,127) BR=(255,127); panel boundary labels "Panel1 Left x=0", "Seam x=128", "Panel2 Right x=255" (top row) and matching on bottom; horizontal seam label "Seam y=64". Verify each label lands on correct physical panel corner/edge. (Covered by AF-106)
11. **≥30 min sustained alternating checkerboards (AF-107).** Full-screen 8×8 checkerboard flip every 2 seconds. 30 min hold. Document: Nano CPU % average, peak, 5-min samples; WF4 IC temp hand/IR or ESP32 IC HCT245 hand/IR temps; no blank / freeze / garble / row-sync drift beyond acceptable delta at end. (Covered by AF-107)
12. **GATE-PASS documentation (AF-108).** Aggregate all evidence: 4 seam photos (vert top, vert bot, horiz, both-center), row sync delta table, coordinate pass photo, 30 min start/end timestamps. Tick 5 DoD bullets. M3 gate = PASS. (Covered by AF-108)

**Success Criteria:**

- **Preferred = every seam check passes (3 vert top + 3 vert bot + 3 horiz + both-center diagonal/circle = 10 seam sub-checks all pass), row sync max delta < 2 s, no thermal >50°C, no blank/freeze 30 min.**
- **Strong preference = all Preferred + Nano CPU average during 30 min run <70%.**
- **Acceptable fallback = any seam visual checks pass (10/10), row sync max delta <5 s acceptable for dashboard usage; thermal up to 60°C OK; Nano CPU up to 85% acceptable.**
- **Failure = any seam visibly broken by >1 px row shift or garbled rows (seam gap or shift visible), or thermal >60°C, or controller crash (blank/freeze requiring manual power cycle during 30 min).**
