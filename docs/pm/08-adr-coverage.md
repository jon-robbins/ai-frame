**Purpose:** Reverse-lookup document mapping every Architecture Decision Record (ADR) from `docs/DECISIONS.md` to the backlog tasks (AF-###) that either **enforce its accepted constraints** (for ACCEPTED ADRs) or **produce evidence used to make its pending decision** (for PENDING/DEFERRED ADRs). ## 2. Legend of ADR Status Values

| Status | Semantics |
|--------|-----------|
| **ACCEPTED** | Accepted constraint; backlog tasks exist that enforce the ADR's decision on the V1 build. Any task violating this ADR should be flagged/reworked. |
| **PENDING** | Decision deliberately deferred pending evidence from M1/M2 experiment results. Resolves at MG (Architecture Decision Gate). Backlog tasks produce the evidence used by the decider. |
| **DEFERRED** | Intentionally put off until a later milestone (typically MF). Decision cannot be made before its predicate inputs (thermal data, dimensions, schematic outputs) all exist. Predicate listed explicitly per ADR. |
| **REJECTED** | Recorded decision **NOT** to do something. Still treated as a constraint on the build (the rejected approach MUST NOT appear in V1). Many REJECTED alternatives live as inline sub-sections within ACCEPTED ADR bodies; they are enumerated in the Accepted-constraint column text of their parent ADR row. |

Note: Status values match `docs/DECISIONS.md` §Status Values (`PROPOSED | ACCEPTED | PENDING | SUPERSEDED | REJECTED | DEFERRED`). No ADR in this table is PROPOSED or SUPERSEDED at time of writing. REJECTED appears as embedded sub-decisions inside several ACCEPTED ADRs.
